## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| type system → runtime | TypeScript types are erased; runtime values must be validated, not assumed from type annotations |
| contract definition → consumers | Any consumer that bypasses the barrel and redefines Role locally breaks the single-source guarantee |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Elevation of Privilege | Role type definition | mitigate | Role is a closed 2-value literal union; no default/fallback that could emit 'owner' exists in the type layer — the parse logic (Plan 02) is the enforcement point |
| T-1-02 | Information Disclosure | identity/authz conflation | mitigate | ResolvedIdentity and Role are separate types in separate callable steps (D-08); a consumer cannot get Role from the identity struct — they are distinct return values |
| T-1-03 | Information Disclosure | principal logged raw | mitigate | 'principal' and 'tokenId' added to SENSITIVE_KEYS in this plan; redactArgs rewrites them to '[REDACTED]' at all log depths ≤ 6 before Phase 4 populates the field |
| T-1-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase — pure TypeScript, zero new dependencies |
</threat_model>
