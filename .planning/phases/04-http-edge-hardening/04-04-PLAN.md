<threat_model>

## Trust Boundaries

| Boundary                     | Description                                                                                                     |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------- |
| HTTP client → handleRequest  | Untrusted request enters; Host/Origin and bearer are validated before any dispatch                              |
| bearer token → TokenEntry    | Token material crosses from request header into auth module; constant-time compare prevents timing oracle       |
| TokenEntry → createSession   | Resolved role crosses from auth layer into session layer; closure captures it for registerTools                 |
| loopback interface → tailnet | Tailscale Serve proxies tailnet→loopback; the loopback bind assertion ensures no direct open-interface exposure |

## STRIDE Threat Register

| Threat ID  | Category               | Component                                               | Disposition | Mitigation Plan                                                                                                                                                                      |
| ---------- | ---------------------- | ------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| T-04-04-01 | Information Disclosure | Timing attack on token compare                          | mitigate    | validateTokenSet uses SHA-256+timingSafeEqual accumulate-then-branch (D-04); implemented in Plan 02, wired here via resolveTokenFromHeader                                           |
| T-04-04-02 | Authentication Bypass  | Silent fallback to agent on bad token                   | mitigate    | D-05: resolveTokenFromHeader returns null → unconditional 401, never a default role                                                                                                  |
| T-04-04-03 | Spoofing               | DNS-rebinding via forged Host/Origin                    | mitigate    | validateHostOrigin middleware rejects unknown Host/Origin before auth (D-14, D-15); OPTIONS also gated                                                                               |
| T-04-04-04 | Elevation of Privilege | Agent session captures owner role from another session  | mitigate    | D-12: role is closure-captured per createSession call; no shared this.role in SessionManager                                                                                         |
| T-04-04-05 | Authentication Bypass  | Conditional auth guard skipped when authToken absent    | mitigate    | D-07: auth gate is unconditional (removed the "if (this.authToken &&" condition); startup assertion ensures token is set                                                             |
| T-04-04-06 | Elevation of Privilege | Funnel exposes server to public internet                | accept      | D-17 structural: loopback bind + mandatory bearer make Funnel harmless; runtime guard deferred to Phase 6. Operator requirement documented in user_setup.                            |
| T-04-04-07 | Elevation of Privilege | Token collision: agent == owner grants owner everywhere | mitigate    | D-06: validateCLIConfig throws on equal tokens (Plan 03); buildTokenRegistry would produce a one-entry map that overrides the first — startup assertion fires before that can happen |
| T-04-04-SC | Tampering              | npm/pip/cargo installs                                  | accept      | No new packages; node:crypto already used in Plan 02                                                                                                                                 |

</threat_model>
