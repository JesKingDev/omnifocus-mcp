    Run the failing tests after each comparator type is added (RED → GREEN cycle).

    The module exports:
    - `type FieldComparatorResult = 'match' | 'mismatch' | 'absent'`
    - `function compareField(fieldName: string, intent: unknown, readBack: unknown): FieldComparatorResult`

    The `compareField` function dispatches to a per-field-type comparator based on `fieldName`.
    Use a registry map (Record of fieldName → comparator function) to keep the dispatch clean and
    extensible.

    DATE fields (dueDate, deferDate, plannedDate, completionDate):
    - Both present: compare as `new Date(x).getTime()` with `Math.abs(diff) <= 60_000`; NaN on
      either side → mismatch.
    - Intent absent, readBack absent or null: match (both unset).
    - Intent present, readBack absent/undefined (key not in object): 'absent' — D-08 hard fail.
    - Intent present, readBack null: mismatch (explicitly cleared).

    TAG field (tags):
    - Apply Set-of-names comparison, case-insensitive (`.toLowerCase()`).
    - ReadBack key absent from object → 'absent'.
    - Different sizes or missing member → mismatch.
    - Same members different order → match.

    SCALAR fields (name, note, flagged, sequential, estimatedMinutes):
    - null/undefined/'' all treated as the same "unset" for string fields (name, note) — unset vs
      unset is match; set vs unset is mismatch.
    - `note`: trim trailing/leading whitespace before comparing.
    - `flagged`, `sequential`: use `normalizeBooleanInput` (from response-format.ts) to coerce
      string 'true'/'false' from MCP bridge. Both null after normalize → match.
    - `estimatedMinutes`: round both sides to integer with `Math.round()` before comparing.
      Both null/undefined → match.
    - Absent key in readBack when intent has a non-null value → 'absent'.

    TYPED-CLASS field (reviewInterval):
    - Compare as JSON structure: `{ unit, steps }`. Both absent → match. Key mismatch → mismatch.

    UNKNOWN field (any fieldName not in the registry): fall back to strict `===` equality; if
    readBack key is absent when intent is non-null → 'absent'.

    Do NOT inline full implementations in code blocks — use the behavior list above as the
    specification. The D-08 absent-field rule is: `Object.prototype.hasOwnProperty.call(readBackObj, key)`
    returning false when intent has a non-null/non-undefined value → return 'absent'.

    After implementation, run `npm run test:unit -- tests/unit/tools/unified/verifier/field-comparator.test.ts`
    and iterate until all tests pass GREEN.
