               identified codebase file (CLAUDE.md, SETTER-PATTERNS.md, etc.) that itself documents the behavior.
             * `evidence: unverified` — claim comes from a community post, API omission, inference, or any other source
               that is neither a live probe nor official doc. Always accompanied by a follow-up note.

           behavior genuinely differs across sub-claims in an area, express nuance via separate per-finding verdicts;
           the area-level verdict is still one value.
         - A note on tombstoning: if a finding is invalidated during the consistency audit, mark it REMOVED (do not
           renumber) to preserve DISC ID stability for downstream phases that may already be drafted.
